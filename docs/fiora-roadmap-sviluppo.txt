# ROADMAP DI SVILUPPO FIORA - PROTOTIPO SU SERVER UBUNTU
 
Analisi basata sulle specifiche tecniche v1.4 e funzionali v1.0
 
================================================================================
 
 
## Fase 0: Setup Infrastruttura (1-2 settimane)
**Priorità:** CRITICA
**Obiettivo:** Preparare l'ambiente di sviluppo sul server Ubuntu
 
**Task principali:**
1. Setup server Ubuntu con Docker e Docker Compose
2. Installazione PostgreSQL 16 con TimescaleDB
3. Installazione Redis 7 per cache e job queue
4. Installazione MinIO per storage foto
5. Installazione Mosquitto MQTT broker
6. Setup Nginx come reverse proxy
7. Configurazione rete privata se multi-server
8. Setup certificati SSL (Let's Encrypt o Cloudflare)
9. Configurazione variabili d'ambiente (.env)
10. Test connettività tra tutti i servizi
 
**Deliverables:**
- Tutti i container Docker attivi e funzionanti
- Database PostgreSQL inizializzato con schema base
- MQTT broker configurato con TLS
- MinIO accessibile e bucket creati
 
--------------------------------------------------------------------------------
 
## Fase 1: Backend Core + Autenticazione (2-3 settimane)
**Priorità:** CRITICA
**Obiettivo:** API REST funzionante con autenticazione completa
 
**Dipendenze:** Fase 0
 
**Task principali:**
1. Setup progetto Node.js/Express con TypeScript
2. Configurazione Prisma ORM con PostgreSQL
3. Implementazione schema database completo (users, plants, tasks, species, etc.)
4. API autenticazione: registrazione email/password
5. API autenticazione: login email/password
6. Sistema JWT (access token + refresh token)
7. Middleware di autenticazione
8. Rate limiting per login
9. Gestione eliminazione account con periodo di grazia
10. Setup BullMQ per job schedulati
11. Job eliminazione account definitiva
12. Test end-to-end autenticazione
 
**Deliverables:**
- API /auth/* completamente funzionanti
- Token JWT funzionanti e validati
- Database schema completo deployato
- Sistema job queue operativo
 
--------------------------------------------------------------------------------
 
## Fase 2: Gestione Piante - MVP (2-3 settimane)
**Priorità:** ALTA
**Obiettivo:** CRUD piante con catalogo specie base
 
**Dipendenze:** Fase 1
 
**Task principali:**
1. API creazione pianta (POST /plants)
2. API lista piante utente (GET /plants)
3. API dettaglio pianta (GET /plants/:id)
4. API modifica pianta (PATCH /plants/:id)
5. API archiviazione/eliminazione pianta
6. Catalogo specie interno curato (20-30 specie comuni)
7. API ricerca specie (GET /species/search)
8. Upload foto piante: integrazione MinIO
9. Ridimensionamento e conversione immagini (Sharp + WebP)
10. API posizioni casa (opzioni dinamiche)
11. Filtri collezione (piante/bouquet, con vaso)
12. Stati pianta (attivo/archiviato/eliminato)
 
**Deliverables:**
- CRUD piante completo e testato
- Catalogo specie interno funzionante
- Upload e storage foto operativo
- API per gestione collezione
 
--------------------------------------------------------------------------------
 
## Fase 3: Sistema Reminder e Task (2-3 settimane)
**Priorità:** ALTA
**Obiettivo:** Generazione automatica reminder e gestione task
 
**Dipendenze:** Fase 2
 
**Task principali:**
1. Implementazione logica calcolo frequenze reminder per clima
2. Job BullMQ per generazione reminder periodici
3. API task giornalieri (GET /tasks/today)
4. API completamento task (POST /tasks/:id/complete)
5. API rimanda task (POST /tasks/:id/postpone)
6. API salta task (POST /tasks/:id/skip)
7. API creazione task manuale
8. Storico azioni (action_logs)
9. Logica prioritizzazione task (sensore > calendario)
10. Calcolo prossima data reminder dopo completamento
11. Modulazione frequenze per clima utente
 
**Deliverables:**
- Sistema reminder automatico funzionante
- API task complete con tutte le azioni
- Job schedulati per reminder attivi
- Storico azioni tracciato
 
--------------------------------------------------------------------------------
 
## Fase 4: App Mobile React Native - Base (3-4 settimane)
**Priorità:** ALTA
**Obiettivo:** App mobile con funzionalità core
 
**Dipendenze:** Fase 3
 
**Task principali:**
1. Setup progetto React Native con Expo SDK 51
2. Configurazione TypeScript strict mode
3. Setup Zustand per state management
4. Implementazione navigazione Expo Router
5. Setup Axios con interceptor per refresh token
6. Schermata login/registrazione
7. Gestione token con SecureStore
8. Onboarding: selezione clima
9. Schermata collezione con lista piante
10. Schermata dettaglio pianta
11. Schermata aggiunta pianta
12. Ricerca specie con autocomplete
13. Upload foto da fotocamera/galleria
14. Schermata Oggi con task giornalieri
15. Azioni task (completa/rimanda/salta)
16. Impostazioni base (profilo, clima)
17. Gestione errori e stati di caricamento
 
**Deliverables:**
- App React Native funzionante su iOS/Android
- Autenticazione completa
- Gestione piante e task operativa
- UI/UX base implementata

## Fase 7: Integrazione Vaso Smart (3-4 settimane)
**Priorità:** MEDIA-ALTA
**Obiettivo:** Pairing e gestione vasi smart MQTT
 
**Dipendenze:** Fase 6
 
**Task principali:**
1. API pairing vaso (POST /vases/pair)
2. Generazione credenziali MQTT per dispositivo
3. Configurazione Mosquitto con auth per device
4. Subscriber MQTT backend per telemetria
5. Salvataggio dati sensori in TimescaleDB (hypertable)
6. API dati sensori (GET /vases/:id/readings)
7. Aggregazione dati sensori (media oraria/giornaliera)
8. Calcolo soglie e alert sensori
9. Job alert umidità/temperatura
10. Worker BullMQ per alert urgenti
11. API associazione vaso a pianta
12. Disassociazione e rimozione vaso
13. Gestione Last Will MQTT (vaso disconnesso)
14. Monitoraggio batteria vaso
15. Notifiche batteria scarica
16. UI mobile: indicatori stato sensori
17. UI mobile: grafici storico dati
18. Logica modulazione reminder con sensore attivo
 
**Deliverables:**
- Sistema MQTT completo e funzionante
- Pairing vaso operativo
- Storico dati sensori salvato
- Alert automatici attivi
- UI sensori nell'app mobile

--------------------------------------------------------------------------------
 
## Fase 9: Catalogo Specie Avanzato (3-4 settimane)
**Priorità:** BASSA-MEDIA
**Obiettivo:** Import completo del catalogo Trefle (non solo cache) e contributi utenti
 
**Dipendenze:** Fase 5
 
**Task principali:**
1. Job batch resumable di import integrale catalogo Trefle in tabella `trefle_species_raw` (JSONB, rate limit 120 req/min)
2. Job BullMQ giornaliero di sync `trefle_species_raw` → `species` (rispetta specie con fonte='curato')
3. Mappatura dati Trefle a schema interno
4. Ricerca specie interamente su DB locale (niente più chiamata live a Trefle)
5. API proposta nuova specie (POST /species/propose)
6. Verifica automatica contro `trefle_species_raw` per proposte
7. Stato specie: in_revisione/approvato/rifiutato
8. Area admin: lista specie in revisione
9. Area admin: approvazione/rifiuto con nota
10. Notifica utente su approvazione/rifiuto
11. Flusso modifica e riproposta specie rifiutata
12. Gestione opzioni dinamiche (app_options)
13. API opzioni per categoria (GET /options/:category)
 
**Deliverables:**
- Catalogo a tre livelli operativo
- Contributi utenti abilitati
- Area admin moderazione funzionante
 
--------------------------------------------------------------------------------
